CURRENT ARCHITECTURE / 2026-07-14

肺部 CT 检测、医学知识检索与多轮对话智能体

Martin 是一个本地 CLI 医疗 AI 项目。它让大语言模型负责理解需求和选择工具，让 MONAI、ChromaDB 与报告链分别承担确定的业务工作，并用 SQLite 保存跨重启的聊天历史。

4 Agent Tools SQLite Session Checkpoints ChromaDB Medical RAG MONAI 3D RetinaNet
02 / ARCHITECTURE

一眼看懂系统分工

核心原则是：LLM 负责判断下一步做什么，工具负责真正执行。对话、病例状态、医学知识和日志分别存储，避免把所有状态混在一处。

入口CLI普通中英文交给 Agent，只解析 /list /open /switch 等系统命令
编排AgentExecutor注入病例上下文，携带 thread_id 调用 LangGraph
决策DeepSeek LLM直接回答，或生成一个或多个 tool_calls
执行4 个业务工具检测、检索、病例更新、报告生成
状态持久化与日志SQLite、ChromaDB、audit、log、results
TOOL 01

analyze_image

加载 NIfTI CT，使用 MONAI RetinaNet 检测结节，并把结构化结果写入当前 CaseContext。

TOOL 02

retrieve_knowledge

支持检测结果 JSON 和自由文本两种模式，从 ChromaDB 返回带来源的医学资料。

TOOL 03

generate_report

解析检测结果，调用报告 LCEL 链；LLM 失败时降级为模板报告。

TOOL 04

update_case_context

从自然语言中提取年龄、性别、吸烟史和家族史，保存到当前病例状态。

03 / RUNTIME

一次普通对话如何运行

LangGraph checkpoint 会自动把同一 thread_id 的旧消息带回模型。AgentExecutor 只需要提交本轮用户输入和当前病例摘要。

01CLI 接收输入

handle_agent_v2() 只把以 / 开头的内容识别为本地命令；其余中英文文本全部传给 Agent。

02注入病例摘要

AgentExecutor.invoke() 从当前 CaseContext 生成摘要，并与用户消息一起组成本轮 messages。

03恢复聊天历史

调用配置携带 thread_id。SqliteSaver 读取该 thread 最新 checkpoint，并合并历史消息。

04LLM 决定动作

模型可以直接生成最终回答，也可以调用工具。工具结果以 ToolMessage 返回后，模型继续判断。

05解析与落盘

最终 AIMessage 作为输出打印；LangGraph 保存 checkpoint，AuditLogger 记录工具调用，运行日志写入 log。

# 关键调用关系
handle_agent_v2()
  → build_agent(thread_id=session_id, checkpointer=SqliteSaver)
  → AgentExecutor.invoke({"input": user_input})
  → create_langchain_agent(...).invoke(
      {"messages": messages},
      {"configurable": {"thread_id": session_id}}
    )
  → {"output": final_text, "intermediate_steps": tool_steps}
04 / CT PIPELINE

CT 分析不是一次函数调用

完整病例通常经过检测、知识检索和报告生成三个阶段。Agent 负责把前一步的文本结果整理为下一工具需要的参数。

A / DETECT

MONAI 检测

读取 NIfTI，执行方向、spacing、强度归一化和滑窗推理，输出每个结节的中心、三维尺寸、最大直径和置信度。

B / RETRIEVE

医学知识检索

检测特征被转换为语义查询，从 Lung-RADS、专家共识和诊疗指南中检索最相关片段。

C / REPORT

结构化报告

LCEL 链组合患者信息、结节详情和知识资料，请 LLM 生成 Markdown 报告；异常时使用模板降级。

标准检测字段
total_nodules、nodules、index、diameter、score、center、dimensions
为什么需要字段归一化
工具返回给 LLM 的检测内容目前是格式化文本，不是直接透传 JSON。LLM 重建下游参数时可能翻译字段名，因此代码同时兼容已观察到的中文别名。
05 / SESSIONS

历史会话与当前会话

AuditLogger.session_id 同时作为 LangGraph 的 thread_id。这个统一标识连接 CLI、SQLite checkpoint、病例缓存和审计日志。

命令实际行为是否改变当前会话
/list枚举 SQLite 中唯一 thread_id，按最近更新时间倒序显示标题和 ID。否
/open 1读取第 1 个会话的最新 checkpoint，只展示 HumanMessage 和最终 AIMessage。否
/switch 1用所选 thread_id 重建 AgentExecutor，后续消息继续写入原会话。是
/new生成新 session_id 并创建新的 AgentExecutor；首次真实消息后才产生 checkpoint。是
/back打印返回提示。由于 open 本身不切换状态，目前没有额外状态需要恢复。否
/help显示系统支持的斜杠命令；未知斜杠命令不会发送给 Agent。否
/exit结束输入循环并关闭进程级 SQLite checkpointer。结束程序
 
# SessionManager 展示规则
SQLite checkpoints
  → 每个 thread_id 只保留最新 checkpoint 用于列表和详情
  → 第一条真实 HumanMessage 生成标题（清洗、最多 48 字）
  → 过滤内部“病例上下文”注入消息
  → 过滤带 tool_calls 的 AIMessage 和 ToolMessage
  → 最终展示：User / Martin 对话
06 / DATA

五类状态放在哪里

“持久化会话”和“持久化所有业务状态”不是同一件事。当前 SQLite 保存对话 checkpoint，但 CaseContext 对象仍是进程内缓存。

data/sessions.sqlite跨重启保存 LangGraph messages 和 checkpoint 状态
ChromaDB/持久化医学文档向量和 metadata
AgentExecutor._context_cache按 thread_id 隔离 CaseContext，仅当前 Python 进程
audit/ 与 log/工具审计、系统日志和 Agent 运行日志
results/检测 JSON 和生成的 Markdown 报告
内容重启后保留主要读取者
完整用户/Agent 消息是LangGraph、SessionManager
医学知识向量是Retriever
结构化患者与结节状态否（对象本身）AgentExecutor、Tools
工具调用审计是开发排查、审计
模型权重是MONAI、Embedding
07 / CODE MAP

按职责阅读代码

第一次看项目建议按入口 → 会话 → Agent → 工具 → 领域实现的顺序，不要从底层模型文件开始。

martin/__main__.py

CLI 与命令路由

main() 处理子命令；handle_agent_v2() 是当前多轮 Agent 入口。

martin/agent/sessions.py

会话访问层

创建进程级 SqliteSaver、列出 thread、提取可展示对话并关闭连接。

martin/agent/agent.py

Agent 编排层

创建 LangChain Agent、注入 CaseContext、运行 LangGraph、解析工具步骤和最终回答。

martin/agent/tools.py

业务工具边界

四个 @tool 的参数协议、异常处理、字段归一化和上下文同步都在这里。

martin/vision/nodule_detector.py

视觉推理

构建 MONAI 3D RetinaNet、加载权重、预处理 CT、滑窗推理并解析结节。

martin/rag/

RAG 基础设施

文档加载、切分、BGE embedding、ChromaDB vector store 和语义检索。

martin/llm/chain.py

报告链

组合知识、患者和结节信息，调用 LLM，并提供模板报告降级路径。

martin/agent/case_context.py

结构化病例状态

保存患者、图像、结节、知识摘要和临床备注，限制注入模型的长度。

tests/

行为证据

覆盖工具、病例上下文、Agent 管线、SQLite 持久化、RAG 和 MONAI 模块。

08 / RUN

启动与依赖关系

项目使用本地 monai_learning Conda 环境。首次运行前需要 DeepSeek 兼容 API 配置、视觉权重、Embedding 模型和已导入的 ChromaDB。

# 推荐入口
conda activate monai_learning
cd E:\moani\medical_ai_agent
python -m martin agent

# main.py 目前委托给同一个 handle_agent_v2()
python main.py

# 首次导入或重建知识库
python scripts\import_knowledge.py

本地计算

MONAI + PyTorch 执行 CT 推理；BGE 模型生成检索向量；SQLite 和 ChromaDB 保存本地数据。

外部调用

ChatOpenAI 使用 OpenAI 兼容协议访问配置的 DeepSeek 模型服务，负责 Agent 决策和报告文本生成。

09 / BOUNDARIES

当前版本的真实边界

这些不是流程图里的抽象问题，而是继续开发时最值得优先处理的具体事项。

HIGH

模型权重缺失仍继续运行。 NoduleDetector 当前只记录警告，然后使用未加载训练权重的网络。医疗结果可能无意义，应改为 fail fast。

MEDIUM

CaseContext 没有独立持久化。 SQLite 能恢复聊天消息，但重启后 Python 中的结构化病例对象会重新创建。

MEDIUM

检测工具返回格式化文本。 下游 JSON 由 LLM 重建，存在字段漂移风险；已有归一化兼容，但更稳妥的是保留结构化工具结果。

MEDIUM

日志包含病例与工具参数。 audit 和 thinking 日志适合开发排查，但用于真实患者数据前需要脱敏、权限控制和保留策略。

LOW

back 命令没有实际导航状态。 open 只查看、不切换，因此 back 当前仅输出提示，可以简化或重新定义详情模式。

LOW

仍是 Alpha CLI。 尚无 Web UI、用户鉴权、并发会话服务和正式医疗验证，不应作为临床诊断结论使用。
