# Martin Quality Runtime

## 工作流

1. 先从变更范围选择最小相关测试，再根据风险扩展到 API、会话、RAG、视觉或前端构建检查。
2. 所有 Python 测试、语法检查和测试工具仅使用 `AGENTS.md` 规定的环境或测试包装器。
3. 在交付前检查工作树，避免提交模型、病例影像、SQLite/Chroma 数据、审计日志、构建缓存或本机可执行文件。

## 质量与隐私门禁

- Agent/审计日志不得存储完整 Chain-of-Thought；限制用户原文、工具参数和最终回答的明文持久化，优先结构化、脱敏依据。
- 全量测试超时或依赖真实模型时，报告已运行的范围、未覆盖的范围和原因，不能把未完成测试写成通过。
- 前端变更运行 `npm run build`；后端变更运行相应 API/单元测试；跨层会话修改覆盖恢复后继续对话和报告生成。
- 本地 API key、患者数据、对象存储凭据和绝对机器路径都不能进入仓库或示例输出。

## 参考

测试命令以 `AGENTS.md` 为准；测试分层和重复项审计见 `docs/CLEANUP_AUDIT.md`。
